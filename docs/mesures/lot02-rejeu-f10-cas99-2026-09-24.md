# F10 — rejeu du cas 99, 6 tirages, avec le correctif (2026-09-24)

**Protocole.** Les 6 versions générées du cas 99 (3 de la mesure de base du lot 12, 3 de la campagne « après »)
sont rejouées par `BehaveRunner` + `Executor` avec le code du lot 02 (décision D12) contre l'instance locale
(`localhost:10017`), sur une copie des données, sans appel LLM. Chaque tirage soumet le formulaire de retenue
de garantie ; le serveur répond HTTP 500 (`KeyError: 0`, équipe de support absente, voir
`lot02-analyse-f10-cas99-2026-09-24.md`) : aucun ticket n'est créé.

**Ce qui change, ce qui ne change pas.** Le STATUT reste `non_conforme` — c'est la décision D12 (un 5xx sur une
action censée réussir est un défaut serveur prouvé). Ce qui change : la CAUSE (`erreur_serveur_5xx` au lieu de
« assertion métier en échec » précédée d'un faux « refus silencieux »), et la PREUVE : le code HTTP reçu et le
message affiché par la page sont dans le résultat, au lieu d'un message qui affirmait « ni la page ni le serveur
n'ont donné de raison » alors que les deux en avaient donné une. Les tirages passent tous par `then` (le constat
de création), et aucun n'est envoyé en réparation automatique (`vrai_bug`).

**Limite.** Qu'il s'agisse d'un défaut de l'application ou d'une copie de base sans équipe de support, seul le
journal serveur le dit ; l'outil constate un plantage serveur sur une saisie que le navigateur a acceptée.
