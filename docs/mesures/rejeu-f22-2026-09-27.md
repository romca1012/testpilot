# F22 — rejeu avant/après (2026-09-27)

**Objet.** F22 (génération 17.0 du banc, 2026-09-25, 1 cas sur 15) : l'agent, ne connaissant que
`ODOO_USER`/`ODOO_PASSWORD`, avait besoin de se connecter avec un compte **secondaire**
(`banc_commercial`) pour un scénario de droits — et n'avait aucun moyen de connaître son mot de
passe. Il en invente un, la connexion RPC est refusée (`Wrong login ID or password`), le cas
tombe en `technical_error`. L'artefact généré exact de cette tentative n'existe plus (dossier
`data_dir` de la mesure d'origine vide — nettoyé depuis) : le rejeu reproduit **le même geste**
(un mot de passe deviné pour le même compte, sur la même instance), pas l'octet exact du fichier
perdu — même esprit que F2/F17, appliqué à la preuve disponible.

**Protocole.** Rejeu réel via `BehaveRunner` + `Executor` + `verdict.status`, contre l'instance
Odoo du banc déjà démarrée (`banc-odoo-odoo-1`, `127.0.0.1:18069`, base `banc`, compte
`banc_commercial` créé par `banc/init_comptes.py`). Aucun appel LLM. Deux scénarios :

- **Avant** — le geste exact de F22 : un step (écrit à la main, imitant ce qu'un agent sans D8
  écrirait) ouvre une session RPC séparée avec `banc_commercial` et un mot de passe **inventé**.
- **Après** — le step officiel du lot 07b-1 : `Quand je me connecte en tant que "Commercial"`,
  avec le **vrai** mot de passe transmis par `TESTPILOT_COMPTES` (jamais écrit par l'agent — le
  message de génération ne porte que le libellé, voir `_section_comptes`).

| | Mécanisme | Axe exécution | Erreur |
|---|---|---|---|
| **Avant** (F22, sans D8) | mot de passe inventé pour `banc_commercial` | **`technical_error`** | `odoorpc.error.RPCError: Wrong login ID or password` |
| **Après** (lot 07b-1, D8) | `je me connecte en tant que "Commercial"` (compte déclaré) | **`success`** | — |

L'axe fonctionnel de l'« après » est `indetermine` (« Aucune vérification exécutée ») : le
scénario ne prouve que la **connexion**, il ne porte aucune assertion métier — c'est le point
exact que F22 documente, rien de plus n'est revendiqué ici.

**Sortie brute** (horodatage retiré) :

```
== AVANT (F22, sans D8) ==
execution: technical_error | fonctionnel: indetermine | erreur: odoorpc.error.RPCError: Wrong login ID or password

== APRES (D8, lot 07b-1) ==
execution: success | fonctionnel: indetermine | erreur: Aucune vérification exécutée
```

**Conclusion.** F22 est corrigé par le lot 07b-1 : l'agent n'a plus jamais à écrire ni à deviner
un identifiant ou un mot de passe pour un compte secondaire — il se limite au libellé déclaré sur
le projet, et le runtime résout le vrai secret.
